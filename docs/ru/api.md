# HTTP API

[Проект](../../README.ru.md) · [Документация](../README.md) · [English](../en/api.md)

Все `/v1` используют необязательный `Authorization: Bearer <key>`. Ключ определяет владельца задания; разные владельцы не могут читать чужие задания, текст и аудио. Открытый `/healthz` показывает готовность, фактическое число потоков, голоса и лимиты без имён клиентов и содержимого.

## Отправить текст

`POST /v1/audio/speech` ждёт и возвращает бинарное аудио. `POST /v1/audio/jobs` возвращает сохраняемое задание с HTTP 202. Оба принимают:

```json
{
  "model":"silero-ru-v5.6",
  "input":"В 2026 году вышло 45 серий. Python и GPT-4.",
  "voice":"xenia",
  "response_format":"opus",
  "speed":1,
  "text_mode":"auto",
  "lexicon":{}
}
```

Обязателен только `input`. Голоса: `xenia`, `eugene`, `aidar`, `baya`, `kseniya`; форматы: `mp3` по умолчанию, `opus`/`ogg`, `wav`; скорость — 0,25–4 с сохранением высоты голоса. `text_mode` — `auto` или `prepared`. Словарь принимает до 256 записей: непустой оригинал до 200 символов и произношение до 500. Неизвестные поля отклоняются. Правила произношения и проверки описаны в [подготовке текста](usage.md).

Модель по умолчанию — `silero-ru-v5.6`; явно переданный ID должен совпадать с ней. В подготовленном тексте `*завтра*` задаёт центр вопроса, а `**важно**` — произнесение с нажимом. Выделять можно одно целое русское слово, пунктуация остаётся снаружи звёздочек. В `auto` Markdown не задаёт интонацию.

Для повторов передавай постоянный `Idempotency-Key` из 1–200 видимых ASCII-символов. Повтор возвращает то же задание, включая ошибочное или истёкшее; изменение текста или параметров даёт 409. Ключ действует внутри одного владельца. После потери ответа или 429/502/503/504 сохраняй тот же ключ. Обычный синхронный запрос без ключа нельзя автоматически повторять после неопределённого сетевого сбоя.

Синхронный запрос без ключа отменяется при отключении клиента или рестарте сервиса. Задания и синхронные запросы с ключом переживают обрыв. Они не организуют доставку в другое приложение. Синхронное ожидание ограничено 15 минутами; для долгой работы используй API заданий.

## Управлять заданием

| Маршрут | Результат |
|---|---|
| `GET /v1/audio/jobs?offset=0&limit=10` | Задания владельца; лимит 1–20, ограниченный JSON, `next_offset` |
| `GET /v1/audio/jobs/{id}` | Состояние, прогресс, отчёт нормализации, безопасная ошибка и ссылки |
| `GET /v1/audio/jobs/{id}/result` | Готовое аудио с поддержкой HTTP Range |
| `GET /v1/audio/jobs/{id}/source` | Явное скачивание исходного текста UTF-8 |
| `GET /v1/audio/jobs/{id}/normalized` | Полный подготовленный текст, когда сборка уже создала этот артефакт |
| `GET /v1/audio/jobs/{id}/segments?offset=0&limit=10` | До 30 подготовленных частей и их готовность |
| `DELETE /v1/audio/jobs/{id}` | Отмена между фрагментами, остановка текущего кодирования |
| `POST /v1/audio/jobs/{id}/resume` | Возврат ошибочного/отменённого задания с сохранением успешных частей |
| `DELETE /v1/audio/jobs/{id}?purge=true` | Удаление файлов неактивного задания; сначала дождись остановки работы |
| `POST /v1/audio/normalize?offset=0&limit=8000` | Проверка подготовки с тем же телом запроса, без синтеза |

У `normalize` синхронный лимит ввода, смещения считаются в **символах**. У Range-запросов текстовых артефактов и команды CLI `text` смещения **байтовые**. Подготавливаемое или ошибочное задание уже может содержать сохранённые части, даже когда полный подготовленный файл ещё недоступен.

Состояния: `preparing`, `queued`, `running`, `assembling`, `completed`, `failed`, `cancelled`, `expired`. Прогресс показывает байты исходника и подготовки, число фрагментов и повторно использованных частей. Ошибки содержат безопасный код и, когда известно, номер части или смещение исходного блока. В состоянии задания доступны параметры запроса, идентификаторы обработки, а после завершения — размер, длительность, тип, расширение и SHA-256 результата. Текст книги не возвращается неявно.

Продолжение соблюдает лимиты очереди и её общего текста. Отмена действует между фрагментами модели; состояние уже может быть `cancelled`, пока текущая часть или кодировщик останавливается. До остановки resume/purge возвращает 409. Смена модели, нормализатора или параметров сборки блокирует несовместимую незавершённую работу с `configuration_changed`: верни прежнюю конфигурацию или создай новое задание с новым ключом.

## Проверить скачивание

Успешный аудиоответ содержит `X-TTS-Job-ID`, `X-Audio-Duration`, `X-TTS-Model`, `X-Content-SHA256` и ETag с контрольной суммой. Сравнивай скачанные байты с метаданными результата. CLI продолжает частичное скачивание и проверяет размер и SHA-256 до замены итогового пути. Публикуй только целый проверенный результат.

| HTTP-статус | Значение |
|---|---|
| 400 / 422 | Неверный ввод; сбой бинарного синтеза даёт 422 с данными задания |
| 401 | Неверный или отсутствующий ключ при включённой авторизации |
| 404 | Неизвестный ID или чужое задание |
| 409 | Другой запрос под прежним ключом, неготовый результат или работа ещё останавливается |
| 410 | Истёкшее задание/артефакт или отсутствующий сохранённый результат |
| 413 | Превышен лимит текста или тела запроса |
| 429 | Лимит очереди, владельца или общего текста; `Retry-After: 5` |
| 504 | Истекло синхронное ожидание; работа с ключом остаётся доступной |
| 507 | Исчерпан бюджет состояния или место на диске |

В API заданий сбой после приёма виден как `state=failed` в состоянии задания; сам запрос приёма уже завершился успешно. Лимиты и сроки хранения описаны в [эксплуатации](operations.md).
