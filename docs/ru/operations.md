# Установка и эксплуатация

[Проект](../../README.ru.md) · [Документация](../README.md) · [English](../en/operations.md)

## Установить сервер

Опубликованный образ рассчитан на Linux AMD64, включает CPU PyTorch и FFmpeg. Docker Compose по умолчанию читает `.env`. Начни с [команд README](../../README.ru.md); храни настройки приватно, а в рабочей установке закрепляй `TTS_IMAGE` проверенным релизом или digest.

[`.env.example`](../../.env.example) служит справочником настроек. Compose использует `TTS_BIND_ADDRESS`, `TTS_PORT`, `TTS_IMAGE`, `TTS_MODELS_PATH`, `TTS_DATA_PATH` и `TTS_ENV_FILE`; приложение получает настройки синтеза, очереди и хранения из своего окружения. Если файл окружения нестандартный, передавай его и самому Compose:

```sh
docker compose --env-file /absolute/path/to/bridge.env up -d --wait --wait-timeout 300
```

В этом файле можно задать `TTS_ENV_FILE=/absolute/path/to/bridge.env`, чтобы использовать его и как окружение контейнера. Подстановка переменных Compose и контейнерный `env_file` — отдельные механизмы. Каталоги хоста должны быть доступны для записи UID 1000; стандартные именованные тома не требуют ручной настройки владельца.

| Путь | Содержимое | Сохранять при обновлении? |
|---|---|---|
| `/models` | Скачанная модель с закреплённой контрольной суммой | Да; можно восстановить с официального хоста |
| `/state` | SQLite/WAL, исходники, подготовленный текст, части, результаты, необязательный файл ключей | **Да**; нужен для восстановления заданий |
| `/tmp` | Ограниченный временный tmpfs | Нет |

Контейнер работает с UID/GID 1000, корневой файловой системой только для чтения и сброшенными capabilities. Обычное обновление не должно удалять том состояния.

## Настроить доступ

По умолчанию доступен localhost. Для удалённых клиентов используй частный интерфейс с HTTPS-прокси или шифрованную частную сеть. `TTS_API_KEY` задаёт одного владельца; для разных приложений укажи `TTS_KEYS_FILE=/state/client-keys.json`:

```json
{"bot-a":"replace-with-a-long-random-key","bot-b":["new-random-key-at-least-24-characters","old-key-during-rotation-only"]}
```

Ключи клиентов должны быть уникальными, не короче 24 символов. Каждому владельцу нужен хотя бы один ключ; пустой список останавливает запуск. Ключи одного имени имеют доступ к тем же заданиям, поэтому пересечение старого и нового ключей позволяет сменить доступ без переноса владения. Замени приватный файл и перезапусти сервис, затем проверь новый ключ перед удалением старого. Доступ к файлам — только владельцу; ключам не место в Git, аргументах и логах.

## Рассчитать объём и хранение

По умолчанию: 12 000 символов и 20 MiB результата для синхронного входа; 5 млн символов и 2 GiB для заданий; восемь активных заданий и 10 млн символов очереди. Один владелец занимает не больше половины очереди, но его индивидуальный лимит не меньше двух; общий лимит действует всегда. Новые и возобновляемые задания проходят одинаковый приём.

Целевой удаляемый кеш — 2 GiB, рабочий бюджет состояния — 20 GiB. Файлы текущего синтеза и кодирования защищены, в том числе при остановке после отмены. Активная работа может превысить целевой размер кеша, но ограничена рабочим бюджетом и свободным диском. При оценке учитываются текст, его копии в базе и создаваемый результат. Это консервативный рабочий бюджет, а не файловая квота: для индексов, служебных данных SQLite и остатков аварии тоже нужно свободное место.

Готовые результаты старше пяти минут могут удаляться под давлением кеша. Семидневный срок по умолчанию также удаляет исходники, подготовленный текст и ошибочную/отменённую работу. Истёкшее задание показывает `expired`; старый ключ не запускает скрытый повтор. Отметки об истечении хранятся ещё два настроенных срока после удаления файлов, затем ключ можно использовать заново. Постоянные публикации скачивай в хранилище приложения.

Для книг выбирай сжатый формат. Предсказуемый размер PCM в WAV проверяется во время синтеза; остальные форматы ограничиваются при сборке и проверяются по полной длительности. Неудачный результат не выдаётся за частичный успех; совместимые фрагменты можно использовать для другого формата.

## Обновить и восстановить

```sh
git pull --ff-only
docker compose pull
docker compose up -d --wait --wait-timeout 300
python3 scripts/smoke.py
```

При нестандартной конфигурации добавляй тот же `--env-file` ко всем командам Compose. Перед скачиванием релиза явно меняй закреплённый `TTS_IMAGE`. Для smoke-проверки задай `TTS_BASE_URL` как корень сервера без `/v1` и `TTS_API_KEY`, если включена авторизация. Проверка озвучивает короткий искусственный текст и проверяет сигнатуру Opus, ID задания и SHA-256.

Запускай **один Uvicorn worker**. Второй процесс не получит исключительную блокировку состояния. По умолчанию PyTorch использует два фактических потока; настройка применяется после загрузки модели и видна в `/healthz`. Увеличение проверяй на своём железе.

После рестарта сохраняемые задания продолжаются с зафиксированных блоков и частей, а прерванное кодирование запускается снова из фрагментов без потерь. Синхронные запросы без ключа отменяются. Отсутствующие или повреждённые части создаются заново; несовместимые настройки дают явную ошибку. `resume` повторяет неудачный этап с текущими лимитами очереди. Несовместимость конфигурации он не обходит.

Для резервной копии останови сервис и скопируй весь приватный каталог или том состояния, включая ключи и сопутствующие файлы SQLite. Модель храни отдельно или скачай заново с закреплённой суммой. Для восстановления верни полное состояние в доступный для записи том, выставь совместимые настройки синтеза и запусти один процесс. Локальные контрольные точки не защищают от потери диска хоста.

## Разобраться со сбоем

| Симптом | Что проверить или сделать |
|---|---|
| Запуск остаётся unhealthy | `docker compose logs --tail 60`; скачивание/сумма модели, запись в тома, структура ключей |
| Модель показывает один поток | `/healthz`, фактический образ и `SILERO_CPU_THREADS` |
| 429 при приёме или продолжении | Подождать и повторить с тем же ключом; перед увеличением лимита посмотреть активные задания |
| `unsupported_text` | Проверить подготовленный блок; добавить произношение или готовую речевую копию |
| `configuration_changed` | Вернуть записанные настройки модели/нормализации/сборки либо создать запрос с новым ключом |
| 507 / `storage_limit` | Проверить диск и бюджет; удалить ненужные неактивные задания, затем продолжить |
| Истёкший или отсутствующий файл | Отправить исходник с новым ключом; в CLI для этого есть `--refresh` |
| Истекло ожидание CLI | Задание сохранено; использовать `status` или `wait` с его ID |

`/healthz` показывает готовность рабочего процесса и общие сведения об очереди. Логи содержат рабочие ID и счётчики, без исходных текстов и тел провайдеров. Внешний брокер, ASR-провайдер и локальная модель на клиентах не нужны.
