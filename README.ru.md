# Silero TTS Bridge

[English](README.md) · [Русский](README.ru.md)

Сервер русской озвучки для коротких ответов и целых книг. Одна CPU-модель Silero v5.5 обслуживает все приложения: Bridge готовит текст, сохраняет прогресс, чередует фрагменты разных заданий и собирает проверенный MP3, OGG/Opus или WAV.

Совместимый с OpenAI `POST /v1/audio/speech` по-прежнему возвращает бинарное аудио. Длинные запросы используют ту же очередь через API сохраняемых заданий. Клиентам не нужны PyTorch и FFmpeg; для комплектного CLI достаточно стандартной библиотеки Python.

## Запуск

Нужен Docker Compose на Linux AMD64. Модель скачивается один раз, проверяется по SHA-256 и хранится отдельно от образа.

```sh
git clone https://github.com/Krablante/silero-tts-bridge.git
cd silero-tts-bridge
cp .env.example .env
docker compose up -d
curl --fail http://127.0.0.1:8000/healthz
```

По умолчанию порт доступен только на localhost. Перед использованием с другого хоста настрой частный адрес и авторизацию. Compose хранит `/models` и `/state` в отдельных постоянных томах. **Сохраняй `/state` при обновлениях**: там находятся задания, исходные и подготовленные тексты, фрагменты и результаты. `TTS_MODELS_PATH` и `TTS_DATA_PATH` выбирают каталоги хоста; контейнеру с UID 1000 нужна запись.

```sh
curl --fail-with-body http://127.0.0.1:8000/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: first-example' \
  --data '{"model":"silero-ru-v5.5","input":"В 2026 году вышло 45 серий. Python и GPT-4.","voice":"xenia","response_format":"opus","speed":1}' \
  --output speech.ogg
```

Голоса: `xenia`, `eugene`, `aidar`, `baya`, `kseniya`. Форматы: `mp3`, `opus`/`ogg`, `wav`. Скорость — 0,25–4 с сохранением высоты голоса.

## Работа с другого хоста

Скачай `silero-tts.py` из [релиза](https://github.com/Krablante/silero-tts-bridge/releases) или используй `client.py` из исходников. Нужен Python 3.10+. Задай `SILERO_TTS_URL` и `SILERO_TTS_API_KEY` либо создай приватный `~/.config/silero-tts/client.json`:

```json
{"base_url":"https://your-private-speech-host.example","api_key":"your-private-client-key"}
```

Права каталога — 0700, файла — 0600. `SILERO_TTS_CONFIG` или `--config` выбирает другой файл. Адрес может оканчиваться на `/v1`.

```sh
python3 client.py voices
python3 client.py speak --text 'Стоимость — 543.21 RUB.' --voice kseniya -o reply.ogg --format opus
python3 client.py speak book.txt --voice xenia -o book.mp3
python3 client.py speak book.txt --voice xenia --no-wait
python3 client.py status tts_REPLACE_WITH_RETURNED_ID
python3 client.py wait tts_REPLACE_WITH_RETURNED_ID -o book.mp3
python3 client.py segments tts_REPLACE_WITH_RETURNED_ID --offset 0 --limit 10
python3 client.py text tts_REPLACE_WITH_RETURNED_ID --max-chars 4000
python3 client.py cancel tts_REPLACE_WITH_RETURNED_ID
python3 client.py resume tts_REPLACE_WITH_RETURNED_ID
python3 client.py clean tts_REPLACE_WITH_RETURNED_ID
```

`speak` по умолчанию ждёт результат и перед ожиданием печатает ID. Прерывание CLI сохраняет задание на сервере. Повтор той же команды использует его снова; отдельно доступны `status` и `wait`. Скачивание продолжается из частичного файла. Готовый путь заменяется только после проверки размера и SHA-256; для замены другого существующего файла нужен `--force`.

`clean` безвозвратно удаляет тексты и результат завершённого задания. Активное сначала отмени и дождись окончания текущего фрагмента. Общие кешированные части могут остаться до очистки кеша.

JSON CLI ограничен 32 000 байтами. `text` возвращает до 8 000 символов и **байтовое** смещение продолжения; `segments` — до 30 частей. Большой текст или аудио не печатаются автоматически. CLI принимает текст; извлечение документов, получение вложений Telegram и публикация остаются задачами приложения.

## Подготовка текста и качество

По умолчанию `text_mode=auto` использует закреплённый `rutextnorm` и общие правила чтения дат, годов, величин, денег, точных дробей, сокращений и технических названий. Сырые цифры и латиница не проходят в модель без проверки. Пустая строка между абзацами остаётся жёсткой границей нарезки. Большой текст готовится ограниченными блоками и не занимает цикл HTTP-запросов целиком.

Bridge сохраняет адреса и слова. Приложение может намеренно убрать ссылки или другой материал **до** отправки. Сам сервер ничего не пересказывает и не выбрасывает незаметно. Пунктуация разметки может упрощаться для произношения.

Для особых названий передай объект `lexicon` или CLI `--lexicon pronunciations.json`:

```json
{"Smith":"Смит","🦊":"лиса"}
```

`text_mode=prepared` принимает уже подготовленную русскую речь, сохраняя проверки и маркеры ударения вроде `к+ошка`. Оставшиеся неподдерживаемые символы дают явную ошибку с кодами и позициями в подготовленном блоке. Из задания доступны оригинал, подготовленный текст и предупреждения нормализации. Координаты предупреждений относятся к исходному блоку с указанным байтовым смещением. Предупреждение означает неоднозначность, а не доказанную ошибку произношения.

Нарезка обязана сохранить все слова. Подготовка внутри модели проверяется на удаление букв; звуковые части — на конечные ненулевые отсчёты, итоговая длительность — на соответствие всем частям, паузам и скорости. Частичный результат не получает статус готового. Эти проверки **не доказывают**, что каждое слово акустически распознаётся верно или любое неоднозначное имя прочитано правильно. Bridge не вызывает ASR и LLM.

## HTTP API

Все `/v1` используют общую необязательную bearer-авторизацию. Открытый `/healthz` показывает готовность, фактическое число потоков, голоса и лимиты очереди, без текстов и имён клиентов.

| Маршрут | Результат |
|---|---|
| `POST /v1/audio/speech` | Ожидание короткого запроса, бинарное аудио при успехе |
| `POST /v1/audio/jobs` | Полный текст, сохраняемое задание, HTTP 202 |
| `GET /v1/audio/jobs?offset=0&limit=10` | Задания текущего клиента с ограниченной страницей |
| `GET /v1/audio/jobs/{id}` | Состояние, прогресс, ошибки и ссылки на файлы |
| `GET /v1/audio/jobs/{id}/result` | Готовый файл с поддержкой HTTP Range |
| `GET /v1/audio/jobs/{id}/source` или `/normalized` | Явное скачивание текста |
| `GET /v1/audio/jobs/{id}/segments?offset=0&limit=10` | Страница подготовленных частей и их готовность |
| `DELETE /v1/audio/jobs/{id}` | Отмена между фрагментами, остановка текущего кодирования |
| `POST /v1/audio/jobs/{id}/resume` | Продолжение ошибочного или отменённого задания |
| `DELETE /v1/audio/jobs/{id}?purge=true` | Безвозвратная очистка файлов неактивного задания |
| `POST /v1/audio/normalize?offset=0&limit=8000` | Ограниченный просмотр подготовки без синтеза |

Оба входа синтеза принимают `model`, `input`, `voice`, `response_format`, `speed`, необязательные `text_mode` и `lexicon`. Для повторов передавай постоянный `Idempotency-Key`. Изменение текста или параметров под прежним ключом даёт 409. Задания принадлежат авторизованному клиенту. Синхронный запрос без такого ключа отменяется при отключении или рестарте; сохраняемые задания переживают потерю соединения. Автоматической доставки сообщений другим приложениям нет.

Состояния: `preparing`, `queued`, `running`, `assembling`, `completed`, `failed`, `cancelled`, `expired`. Модель выполняет один фрагмент за раз. Потоковая сборка имеет отдельный слот для звука до пяти минут и отдельный для длинных результатов: финальное кодирование книги не задерживает короткий ответ. Одновременно работают не больше двух кодировщиков. Рестарт восстанавливает сохраняемые задания; смена модели или нормализатора явно останавливает несовместимую незавершённую работу. Явное продолжение повторяет неудавшийся этап и использует успешные части, пока они не истекли или не вытеснены по лимиту хранения. Ошибки ввода и нормализации явные. Логи содержат рабочие метаданные, без исходных текстов и тел ответов провайдеров.

Аудиоответ содержит `X-TTS-Job-ID`, `X-Audio-Duration`, `X-TTS-Model`, `X-Content-SHA256` и ETag. Переполнение очереди даёт 429 и `Retry-After: 5`. Неизвестные и чужие ID — 404, истёкшие файлы — 410. Ошибки валидации не возвращают присланный текст.

## Доступ и хранение

`TTS_API_KEY` сохраняет прежнюю схему одного ключа. Для отдельных приложений создай приватный `/state/client-keys.json` и укажи этот путь в `TTS_KEYS_FILE`:

```json
{"bot-a":"replace-with-a-long-random-key","bot-b":["new-random-key-at-least-24-characters","old-key-during-rotation-only"]}
```

Ключи одного имени клиента имеют доступ к тем же заданиям: это позволяет менять ключ без потери материалов. Разные имена не могут читать чужие тексты и результаты. Внутренний кеш может использовать одинаковые звуковые части, но публичного поиска по чужому кешу нет. Не храни ключи в скриптах, аргументах команд, Git и логах. Сервер должен оставаться частным; для удалённых соединений используй HTTPS или шифрованную частную сеть.

Значения по умолчанию находятся в `.env.example`: синхронный вход — 12 000 символов и 20 MiB результата; задания — 5 млн символов и 2 GiB результата; восемь активных заданий и 10 млн символов очереди; целевой удаляемый кеш — 2 GiB; рабочий бюджет — 20 GiB; срок хранения — семь дней. Лимиты проверяются при приёме, обработке частей и сборке. Большой WAV может не поместиться, хотя MP3 помещается.

Активные части защищены от вытеснения. Готовые результаты могут удаляться под давлением кеша после пяти минут; срок хранения также распространяется на исходники, подготовленный текст и ошибочные/отменённые задания. Истёкшее задание показывает `expired`, не начинает тайный повтор под старым ключом. CLI `--refresh` создаёт новое задание. Постоянные публикации сохраняй в хранилище приложения. Для восстановления после потери диска копируй приватный `/state` при остановленном сервисе; `/models` воспроизводится отдельно.

## Обновление и проверка

```sh
git pull --ff-only
docker compose pull
docker compose up -d
python3 scripts/smoke.py
```

Для авторизованной проверки задай `TTS_BASE_URL` и `TTS_API_KEY`. В рабочей установке закрепляй `TTS_IMAGE` тегом или digest. Запускай **один Uvicorn worker**: второй не получит блокировку состояния. Настройка потоков применяется после загрузки модели и видна в health. Два потока — исходный баланс; увеличение проверяй на своём железе.

Для разработки нужны FFmpeg и `pip install -r requirements.txt httpx==0.28.1`, затем `python -m unittest discover -s tests -v`. Проверки используют изолированную модель-заглушку с настоящим кодированием и сборкой, без весов и внешних API. Проверки настоящей модели и восстановления входят в выпуск.
